1. Basic Flask App

Let's start from scratch and build your very first Flask web application.

What is Flask?

Flask is a micro web framework for Python. Think of it as a toolkit that lets you turn Python code into a website or web API. It is called "micro" because it gives you the essential building blocks — routing, request handling, responses — without forcing a particular database, template engine, or project layout on you.

Flask was created by Armin Ronacher in 2010. It powers websites at companies like Netflix, Reddit, Lyft, and Zillow.

Why Use Flask?

  • Lightweight — only a few files to get started.
  • Easy to learn — if you know Python, you can build a web app in minutes.
  • Flexible — add only the extensions you need (databases, authentication, etc.).
  • Large community — thousands of tutorials, plugins, and Stack Overflow answers.

Installing Flask

Open your terminal and run:

terminal
1pip install flask

This downloads Flask and its dependencies (Werkzeug, Jinja2, MarkupSafe, itsdangerous, click).

It creates a Flask application object. __name__ helps Flask find the root path of your project so it knows where to look for templates and static files.

2. Flask Web Architecture

Before writing more code, let's understand how a Flask app actually works when someone visits your website.

The Request–Response Flow

Click on each component below to learn what it does:

🌐 Browser (Client)
↓
📨 HTTP Request
↓
🧪 Flask Application
↓
🛤️ @app.route()
↓
🐍 Python Function
↓
📩 HTTP Response
↓
🌐 Browser (Displays)

Detailed Breakdown

Client

The client is whatever makes the request — usually a web browser (Chrome, Firefox), but it could also be a mobile app or another program like curl. The client initiates communication.

Server

The server is the computer (or program) that receives requests and sends back responses. When you run python app.py, your own computer becomes a server.

HTTP Request

When you type http://127.0.0.1:5000/ and press Enter, the browser sends an HTTP request. This request contains:

  • Method — GET, POST, PUT, DELETE, etc.
  • URL — the address you typed.
  • Headers — metadata (browser type, language, cookies).
  • Body — optional data (form submissions).

Route

Flask checks the URL from the request against all the routes you defined with @app.route(). If it finds a match, it calls the corresponding Python function. If no match is found, Flask returns a 404 Not Found error.

View Function

The Python function attached to a route is called a view function (or simply "view"). It processes the request and returns a response — a string, HTML, JSON, or even a file.

HTTP Response

Flask packages the return value of your view function into an HTTP response that includes:

  • Status code — 200 (OK), 404 (Not Found), 500 (Server Error), etc.
  • Headers — content type, cookies, cache instructions.
  • Body — the actual content (your HTML or text).

Browser Renders

The browser receives the response and displays the content. If it's HTML, the browser renders it as a web page. If it's plain text, it shows the text directly.

Every web interaction — clicking a link, submitting a form, loading an image — follows this same request → process → response cycle.
Q: What is the difference between a client and a server?
The client (browser) sends requests. The server (Flask app) receives requests, processes them, and sends back responses.

3. Debug Mode

Debug mode is a developer's best friend while building a Flask application.

What is Debug Mode?

When you set debug=True, Flask enables two helpful features:

  1. Auto-Reloader — Flask watches your Python files. When you save a change, the server restarts automatically. No need to stop and start manually!
  2. Interactive Debugger — If your code has a bug and crashes, Flask shows a detailed error page in the browser with a full traceback, and even lets you run Python code right in the browser to investigate.

Syntax

python
1# Debug mode ON (development)
2app.run(debug=True)
3
4# Debug mode OFF (production)
5app.run(debug=False)

Never use debug=True in production! The interactive debugger lets anyone execute arbitrary Python code on your server. This is a massive security hole. Always set debug=False (or remove the argument entirely) before deploying.
During development on your own computer, always use debug=True. It saves you from constantly restarting the server and helps you find bugs faster.

4. app.route()

Routes are the foundation of every Flask application. They map URLs to Python functions.

What is a Route?

A route is a rule that tells Flask: "When the user visits this URL, call this function."

How @app.route() Works

@app.route() is a Python decorator. It "decorates" the function below it, registering that function to handle a specific URL.

python
1@app.route("/")
2def home():
3    return "Home Page"
@app.route("/")Registers the URL path / (homepage). The @ symbol marks it as a decorator.
def home():The view function that runs when / is visited. The name can be anything, but it should be descriptive.
return "Home Page"The text returned to the browser.

Multiple Routes

You can have as many routes as you need — each one maps a different URL to a different function.

python
1@app.route("/")
2def home():
3    return "Home Page"
4
5@app.route("/about")
6def about():
7    return "About Page"
8
9@app.route("/contact")
10def contact():
11    return "Contact Page"

The URL → Route → Function → Response Flow

Every route URL must start with /. Writing @app.route("about") without the leading slash will cause an error.
Two routes cannot point to the same function name. Each view function must have a unique name, even if the URLs are different.
Q: What is the difference between a URL path and a route?
A URL path (/about) is what the user types in the browser. A route (@app.route("/about")) is the Flask mechanism that maps that URL path to a Python function.

5. GET and POST

HTTP methods tell the server what kind of action the client wants to perform. The two most common methods are GET and POST.

What is GET?

GET means "give me some data." Every time you type a URL or click a link, your browser sends a GET request. It's used to retrieve information without modifying anything on the server.

python
1@app.route("/login", methods=["GET"])
2def login():
3    return "Login Page"
methods=["GET"]Tells Flask this route only responds to GET requests. GET is actually the default, so this is optional — but being explicit is good practice.

What is POST?

POST means "here is some data — process it." It's used when the client sends data to the server, such as submitting a form (login, registration, search).

python
1from flask import request
2
3@app.route("/login", methods=["POST"])
4def login():
5    username = request.form.get("username")
6    return f"Welcome {username}"
from flask import requestImports Flask's request object, which holds all data sent by the client (form data, JSON, headers, etc.).
methods=["POST"]This route only accepts POST requests.
request.formA dictionary-like object containing form data submitted via POST.
.get("username")Safely retrieves the value of the form field named username. Returns None if the field doesn't exist (no crash).

The HTML Form

html
1<form method="POST">
2    <input type="text" name="username">
3    <button type="submit">Submit</button>
4</form>
method="POST"Tells the browser to send the form data using the POST method.
name="username"The key used in request.form.get("username"). The name attribute in HTML matches the key you use in Python.
type="submit"Creates a submit button. Clicking it sends the form data to the server.

A route can accept both GET and POST: methods=["GET", "POST"]. Inside the function, check which method was used with request.method.
Don't use GET for sensitive data like passwords. The data appears in the URL, browser history, and server logs.
Q: What is the difference between request.form and request.args?
request.form → data from POST form body.
request.args → data from GET query string (?key=value).

6. Dynamic Routes

So far every route has been static — a fixed URL like /about. Dynamic routes let you capture part of the URL and use it as a variable in your function.

Basic Dynamic Route

python
1@app.route("/student/<name>")
2def student(name):
3    return f"Student Name: {name}"
<name>A variable rule. Flask captures whatever text appears in this position in the URL and passes it to the function as the parameter name.
def student(name):The function must accept a parameter with the same name as the variable rule.

Example URLs

URL VisitedValue of nameResponse
/student/Ravi"Ravi"Student Name: Ravi
/student/Priya"Priya"Student Name: Priya
/student/Alex"Alex"Student Name: Alex

Type Converters

By default, the captured value is a string. You can force a specific type:

python
1@app.route("/student/<int:id>")
2def student_by_id(id):
3    return f"Student ID: {id}"
ConverterSyntaxAccepts
string (default)<name>Any text without slashes
int<int:id>Positive integers
float<float:price>Floating-point numbers
path<path:filepath>Any text including slashes

Multiple Parameters

python
1@app.route("/student/<name>/<int:id>")
2def student_detail(name, id):
3    return f"Name: {name}, ID: {id}"
<name>/<int:id>Two variables captured from the URL, separated by /. The first is a string, the second an integer.
def student_detail(name, id):Both variables become function parameters. The names must match exactly.

7. url_for()

Hard-coding URLs like "/about" everywhere works, but it becomes a maintenance nightmare when you change a URL. url_for() solves this by generating URLs dynamically based on function names.

What is url_for()?

url_for() is a Flask helper that takes a function name and returns the URL associated with it.

python
1from flask import Flask, url_for
2
3app = Flask(__name__)
4
5@app.route("/")
6def home():
7    return "Home"
8
9@app.route("/about")
10def about():
11    return "About"

Using url_for()

python
1url_for("home")     # Returns: "/"
2url_for("about")    # Returns: "/about"
Notice that url_for() takes the function name (e.g. "home"), not the URL path (e.g. "/"). This means if you later change @app.route("/") to @app.route("/index"), every url_for("home") call automatically generates the new URL.

Why Use url_for()?

  1. Maintainability — Change the URL in one place (the decorator), and all links update automatically.
  2. No typos — If you misspell a function name, Flask raises an error immediately instead of serving a broken link silently.
  3. Handles special characters — url_for() properly escapes special characters in URLs.

url_for() with Dynamic Routes

python
1@app.route("/student/<name>")
2def student(name):
3    return f"Student: {name}"
4
5# Generating the URL:
6url_for("student", name="Ravi")   # Returns: "/student/Ravi"
url_for("student", name="Ravi")Pass dynamic parameters as keyword arguments. The key must match the variable rule name in the route.

The Flow

Function name: "student"
↓
url_for("student", name="Ravi")
↓
Generated URL: /student/Ravi

If you write url_for("students") but your function is named student, Flask raises a BuildError. The name must match the function exactly.
Q: Why should you use url_for() instead of hard-coding URLs?
Because if you change a URL path in the decorator, all url_for() calls automatically use the new path. Hard-coded URLs would break.
